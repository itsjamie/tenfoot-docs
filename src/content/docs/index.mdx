## Why it is fast

A TV app has one hard job. It has to draw a screen full of cards and text, sixty times a second, on a chip ten to fifteen times slower than a laptop. Tenfoot was built for the 2017 TV from day one. You can see that in six places.

<CardGrid>
  <Card title="One GPU program for everything" icon="rocket">
    Shapes, pictures, and text all use the same GPU program. The painter puts them in groups. It starts a new group only when the picture data changes. A home screen with a hero, ten cards, their captions, and a focus ring is about ten draw calls. (A draw call is one request to the GPU to draw.) A gray "not available" look on a card is just a number saved with the shape. It is not a second program. So it costs nothing extra.
  </Card>
  <Card title="No frames when nothing changes" icon="moon">
    The screen draws a new frame only when something asks for one, or when something is moving. A screen that is sitting still draws nothing. Press a key, and it draws the six or seven frames the animation needs. Then it stops. On a TV, that is the difference between a warm box and a hot one. It is why the fan never turns on.
  </Card>
  <Card title="One small record per shape" icon="seti:json">
    Each shape is 18 numbers in one list. The GPU turns them into corners when it can. When it cannot, the CPU does it in a tight loop. There is no tree of web page elements. There are no styles to work out. There is no layout engine to run. The browser's own page layout never touches your app.
  </Card>
  <Card title="No templates, no diffing" icon="seti:config">
    A node is an object with a `paint` method. There is no template language to build. There is no copy of the screen to compare. There is no data binding to run on every change. You write what to draw. That is where most of the speed comes from. It is a choice, not a missing feature.
  </Card>
  <Card title="Memory is a budget, not a hope" icon="seti:image">
    Pictures share space on the GPU and live under a byte limit. When the limit is reached, the pictures used least recently are dropped. Compressed pictures shrink a full-screen backdrop from 8 MB to 1 MB. In the test below, 20,000 items take about 3 MB.
  </Card>
  <Card title="Sized for a 2017 set" icon="laptop">
    The whole core is 38 KB. It uses WebGL 1, because every TV has that. It uses WebGL 2 only when a newer TV offers it. It knows that some TVs do GPU math with 16-bit numbers, and it stays inside that. It has no `async`, no generators, and no `fetch`, because those turn into slow code on a 2017 browser.
  </Card>
</CardGrid>

## The numbers

These come from the Lightning team's open speed test for TV renderers, [lightning-js/benchmark](https://github.com/lightning-js/benchmark). It makes, changes, and removes thousands of items. We ran it on a desktop computer with the CPU slowed down six times. Lower is better.

| Test | Tenfoot |
| --- | ---: |
| create 1,000 items | 3.9 ms |
| create 10,000 items | 21 ms |
| add 10,000 items | 20 ms |
| clear the screen | 3.0 ms |
| 20,000 items in memory | 3.2 MB |
| file size | 38 KB |

These are desktop numbers, not TV numbers yet. Running on a real 2017 set is the first item on the [roadmap](roadmap/). The [why](why/) page has every row, and a full home screen measured the same way: nine rows of posters, a hero, and a fading backdrop hold 60 frames a second in 11 draw calls, even with the CPU slowed twenty times.

## What comes with it

<CardGrid stagger>
  <Card title="Focus that works on a scrolling row" icon="seti:config">
    Your screen says where its cards are. The focus engine does the rest. It remembers where you were, moves between rows the right way, and handles long lists.
  </Card>
  <Card title="What the TV makers check for" icon="approve-check">
    The exit dialog Samsung wants and LG does not. Keeping the screensaver off during video. Working offline. Deep links where Back still works.
  </Card>
  <Card title="Captions that follow the video" icon="open-book">
    A caption layer that keeps time with the video, uses the TV's own caption settings, and stays out of the way of your controls.
  </Card>
  <Card title="Widgets from a real app" icon="puzzle">
    Cards, rows, grids, buttons, and menus. They were built and tested by a sample app with eleven screens. Import them by name, or draw your own.
  </Card>
</CardGrid>
