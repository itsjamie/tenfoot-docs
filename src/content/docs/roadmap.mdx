The renderer is not the weak spot. The things around it are. In order:

1. **Run it on a real TV.** A 2017 LG and a 2017 Samsung. Until then, every number on this site comes from a desktop computer.
2. **The widget tier.** Done, as `tenfoot/ui`, with `theme()` for a second design.
3. **The services every TV app writes anyway.** Storage, translations, device info, usage stats, and a way to clean up timers when a screen closes.
4. **More TV platforms.** Firebolt first, because that is where RDK apps run.
5. **A Canvas 2D fallback** for TVs where WebGL is turned off.
6. **The Lightning speed test.** Done. The results are on the [why](../why/) page.
7. **This site**, a starter project, and a guide for moving from Lightning.
8. **Better animation:** sequences, repeats, delays, and a callback when done.
9. **A full player example**, including DRM.

What it will not do: add a template language or data binding. The speed numbers on the [why](../why/) page come from keeping things simple. That stays.

`docs/DESIGN.md`, which ships in the package, explains the design choices inside the library.
