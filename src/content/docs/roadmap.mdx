Three things are next. If you want to help with any of them, [open an issue](https://github.com/itsjamie/tenfoot-docs/issues).

## Testers

We are looking for people outside the project to build something with Tenfoot and tell us where it gets in the way. You do not need a TV to start. A desktop browser runs everything on this site.

## More devices

Every number on this site comes from a desktop computer so far. We are gathering numbers from real TVs and set-top boxes, starting with 2017 LG and Samsung sets. If you have one and can run a test page on it, we would like to hear from you.

## An easier API

We want Tenfoot to be easier to learn and to take less code to write, without losing its main design.

That design borrows an idea from C++: the zero-cost abstraction. In C++, a well-made helper compiles away. The program you get is the one you would have written by hand. JavaScript cannot promise that. A helper is still a function that runs, and running costs something. So Tenfoot will never be truly zero-cost the way C++ can be.

It aims for the same standard anyway. A helper should draw the same shapes, in the same draw calls, as the code you would have written yourself, and add as little as we can measure on top. When a new helper adds a cost, we measure it, and it has to be worth it.
